# historian2grafana — инструкция по развёртыванию в Docker Desktop и работе

Приложение раз в несколько секунд забирает значения тегов из AVEVA Historian, складывает их в свою базу данных и строит по ней графики: на своей странице и в Grafana. Инструкция идёт по порядку, от чистого компьютера с Windows до графиков: установка Docker Desktop, запуск, подключение к историку, проверка, повседневная работа и разбор неполадок.

## 1. Как это устроено

Приложение состоит из трёх контейнеров Docker, которые запускаются одной командой:

| Контейнер | Что делает | Где открыть |
|---|---|---|
| h2g-app, приложение | Подключается к историку, раз в 5 секунд забирает новые значения тегов и записывает их в базу. Показывает страницы «Подключение», «Загрузка», «Графики» и «Скрипты» | http://localhost:8000 |
| h2g-db, база данных | PostgreSQL 16 с расширением TimescaleDB для временных рядов. Здесь хранятся теги и их значения | снаружи не открывается |
| h2g-grafana, Grafana | Готовый дашборд «Теги историка» по данным базы | http://localhost:3000 |

Данные идут так:

```text
AVEVA Historian (SQL Server, база Runtime)
        │  раз в 5 с: «что нового?», только чтение
        ▼
h2g-app ──запись──► h2g-db (TimescaleDB) ──чтение──► графики в приложении и Grafana
```

В историке приложение выполняет только запросы SELECT, поэтому учётной записи достаточно права на чтение базы Runtime. При первом запуске копируется история за выбранный период (по умолчанию за сутки), потом только новые значения. Для каждого тега приложение помнит, до какого момента он скопирован, так что дублей не бывает, а после перерыва (пропала сеть, выключали компьютер) пропущенное докопируется само. Время в базе хранится в UTC, а на графиках показывается по часам вашего компьютера.

## 2. Что понадобится

| Что | Требование |
|---|---|
| Компьютер | Windows 10 (22H2) или Windows 11, 64-бит. Оперативной памяти от 8 ГБ (лучше 16 ГБ), свободного места на диске от 20 ГБ. В BIOS должна быть включена виртуализация (Intel VT-x или AMD-V) |
| Права | Администратор Windows, но только на время установки Docker Desktop |
| Сеть до историка | С этого компьютера должен открываться сервер историка по TCP-порту 1433 (или другому порту SQL Server). Как проверить, написано в разделе 6 |
| Учётная запись историка | Подойдёт одна из двух:<br>• логин SQL Server с правом чтения базы Runtime. Это самый надёжный вариант, такой логин создаёт администратор историка;<br>• доменная учётная запись Windows, под которой вы входите в SSMS: логин вида ДОМЕН\логин и пароль |
| Интернет | Нужен при первом запуске, чтобы скачать образы Docker (около 1,5 ГБ) и драйверы. Если на нужном компьютере интернета нет, смотрите раздел 13. Там же про комплект без Docker |

> **Важно.** Docker Desktop бесплатен для личного использования, обучения и компаний до 250 сотрудников с выручкой до 10 млн долларов в год. Крупной организации для рабочего использования нужна платная подписка, уточните это в ИТ-службе.

## 3. Установка Docker Desktop

Если Docker Desktop уже установлен и работает, переходите к разделу 4.

1. Откройте страницу https://docs.docker.com/desktop/setup/install/windows-install/ и скачайте «Docker Desktop for Windows – x86_64».
2. Запустите установщик Docker Desktop Installer.exe. На экране настроек оставьте отмеченным пункт «Use WSL 2 instead of Hyper-V (recommended)» и нажмите «Ok».
3. Когда установка закончится, нажмите «Close and restart». Компьютер перезагрузится.
4. Запустите Docker Desktop из меню «Пуск» и примите лицензионное соглашение («Accept»). Входить в учётную запись Docker не обязательно, можно нажать «Skip».
5. Дождитесь, пока внизу слева в окне Docker Desktop появится зелёная надпись «Engine running».
6. Откройте PowerShell (меню «Пуск», наберите «PowerShell») и проверьте:

```powershell
docker version
docker compose version
```

Обе команды должны напечатать номера версий без ошибок.

#### Если что-то пошло не так

| Сообщение | Что сделать |
|---|---|
| WSL 2 installation is incomplete / WSL needs updating | Откройте PowerShell от имени администратора, выполните `wsl --update` и перезагрузите компьютер |
| Virtualization support not detected | Включите виртуализацию в BIOS/UEFI (Intel VT-x, AMD-V или SVM Mode). Проверить можно в Диспетчере задач: Производительность, ЦП, строка «Виртуализация: Включено» |
| error during connect … dockerDesktopLinuxEngine | Docker Desktop не запущен или ещё запускается. Откройте его и дождитесь «Engine running» |
| Компьютер в сети с прокси-сервером | В Docker Desktop откройте Settings, Resources, Proxies, включите Manual proxy configuration и укажите адрес прокси (его знает ИТ-служба) |

Чтобы приложение запускалось само после включения компьютера, в Docker Desktop откройте Settings, General и отметьте «Start Docker Desktop when you sign in to your computer». Контейнеры приложения поднимутся вместе с Docker Desktop.

## 4. Получение проекта

Положите проект в папку без русских букв и пробелов в пути, например `C:\historian2grafana` или `D:\historian2grafana`. Диск подойдёт любой. В примерах ниже путь `C:\historian2grafana`, если у вас другой, подставляйте свой. Получить проект можно так:

- с GitHub через git: `git clone <адрес репозитория> C:\historian2grafana`;
- архивом: на странице репозитория нажмите «Code», затем «Download ZIP», и распакуйте в `C:\historian2grafana`. Внутри сразу должны лежать `docker-compose.yml`, `Dockerfile` и папки `app`, `web`, `grafana`;
- с флешки или по сети: скопируйте папку проекта целиком.

Все команды дальше выполняются в PowerShell из папки проекта. Проще всего открыть PowerShell сразу в ней: откройте папку в Проводнике, щёлкните в адресной строке, наберите `powershell` и нажмите Enter. Можно и перейти в неё командой:

```powershell
cd C:\historian2grafana
```

## 5. Настройка и запуск

### 5.1 Файл .env: порты и пароли

Создайте файл настроек из образца и откройте его в Блокноте:

```powershell
Copy-Item .env.example .env
notepad .env
```

| Параметр | Что значит |
|---|---|
| APP_PORT | Порт приложения на этом компьютере, по умолчанию 8000 |
| GRAFANA_PORT | Порт Grafana, по умолчанию 3000 |
| DB_PASSWORD | Пароль базы данных приложения. Применяется только при первом запуске |
| GRAFANA_DB_PASSWORD | Пароль, под которым Grafana читает базу. Эта учётная запись может только читать значения тегов |
| GRAFANA_ADMIN_USER, GRAFANA_ADMIN_PASSWORD | Логин и пароль для правки дашбордов в Grafana. Применяются при первом запуске Grafana. Смотреть графики можно и без входа |
| TZ | Часовой пояс журналов контейнера (Europe/Moscow). На графики не влияет |
| HISTORIAN_OLD_TLS | Если поставить 1, приложение разрешит устаревшее шифрование для старых SQL Server. Включайте, только если проверка подключения пишет об ошибке SSL/TLS |
| GRAFANA_URL | Адрес Grafana для ссылок из приложения, если её открывают не по адресу этого компьютера. Обычно остаётся пустым |
| LOG_LEVEL | Подробность журналов: INFO или DEBUG |

Подключение к историку в этом файле не задаётся, его вводят в браузере (раздел 7). Без файла `.env` приложение тоже запустится, с паролями по умолчанию. Для проверки этого хватит, а для постоянной работы пароли лучше поменять.

### 5.2 Запуск

```powershell
docker compose up -d --build
```

Первый запуск занимает 5–15 минут: Docker скачивает образы базы и Grafana, собирает образ приложения и ставит в него драйверы SQL Server. Потом запуск занимает секунды.

Проверьте, что все три контейнера работают:

```powershell
docker compose ps
```

В столбце STATUS у `h2g-db` и `h2g-app` должно стоять `Up … (healthy)`, у `h2g-grafana` просто `Up`. То же самое видно в Docker Desktop на вкладке «Containers», в группе «historian2grafana».

Откройте в браузере http://localhost:8000. Появится страница «Подключение».

> **Совет.** Если страница не открывается, посмотрите журнал приложения: `docker compose logs --tail 50 app`. Частые причины разобраны в разделе 14.

## 6. Проверка сети до историка

Прежде чем вводить настройки, убедитесь, что сервер историка вообще доступен с этого компьютера. Выполните в PowerShell, подставив имя своего сервера вместо HISTSRV01:

```powershell
Test-NetConnection HISTSRV01 -Port 1433
```

В ответе должна быть строка `TcpTestSucceeded : True`. Если там `False`, сервер по сети недоступен. Проверьте имя и порт и спросите администраторов про брандмауэр: пока это не исправлено, приложение тоже не подключится.

Затем проверьте то же самое изнутри контейнера. Приложение работает именно там, а имена компьютеров контейнер ищет немного иначе, чем Windows:

```powershell
docker compose exec app python -m app.check HISTSRV01 1433
```

Ответ `✓ адрес … ✓ открыт` означает, что всё в порядке. Бывает, что Windows сервер находит, а контейнер пишет «не находится». Тогда используйте полное имя сервера с доменом или его IP-адрес. Узнать их можно так:

```powershell
Resolve-DnsName HISTSRV01
```

В строке Name будет полное имя (например `HISTSRV01.corp.local`), в IPAddress адрес. Подставьте их сначала в проверку из контейнера, а потом в поле «Сервер историка».

#### Как узнать имя, адрес и порт через SSMS

Подключитесь к историку в SSMS как обычно и выполните запрос:

```sql
SELECT @@SERVERNAME AS server_name,
       CONNECTIONPROPERTY('net_transport') AS transport,
       CONNECTIONPROPERTY('local_net_address') AS ip_address,
       CONNECTIONPROPERTY('local_tcp_port') AS tcp_port;
```

Если `transport` не TCP, а `ip_address` пустой, значит, SSMS подключён не по сети (например, вы работаете прямо на сервере). Тогда адрес придётся спросить у администратора. Если SQL Server работает именованным экземпляром (в SSMS сервер записан как `СЕРВЕР\ЭКЗЕМПЛЯР`), его порт часто не 1433. Возьмите `tcp_port` из этого запроса.

### 7.1 Сервер

| Поле | Что вписать |
|---|---|
| Сервер историка | Имя компьютера, как в поле Server name в SSMS (например `HISTSRV01`). Надёжнее указать полное имя с доменом или IP-адрес (раздел 6). Именованный экземпляр пишется как `СЕРВЕР\ЭКЗЕМПЛЯР` |
| Порт | Оставьте пустым, будет стандартный 1433. Другой порт нужен, только если SQL Server слушает его |
| База | `Runtime`, база AVEVA Historian. Менять не нужно |

### 7.2 Вход

Есть два способа войти в историк.

Логин SQL Server: отдельный логин с правом чтения базы Runtime. Он надёжнее всего, потому что не зависит от домена и политик Windows. Попросите администратора историка создать такой логин с ролью db_datareader в базе Runtime.

Учётная запись Windows: та, под которой вы входите в SSMS. Логин пишется вместе с доменом, например `CORP\ivanov`, пароль от этой учётной записи. Приложение войдёт по протоколу NTLM, так же, как SSMS с другого компьютера.

![Вход учётной записью Windows: логин вместе с доменом](img/connection-windows.png)

*Рис. 2. Вход учётной записью Windows: логин вместе с доменом*

> **Примечание.** Пароль хранится в базе приложения и в интерфейсе не показывается. Если поле пароля оставить пустым, сохранённый пароль не изменится. Если пароль учётной записи Windows сменился, введите новый и нажмите «Сохранить».

> **Важно.** Войти учётной записью Windows из Docker можно, только если SQL Server принимает вход по NTLM. Обычно принимает. Если проверка при верном пароле пишет «Login failed» или «соединение оборвалось при входе», попросите у администратора логин SQL Server.

### 7.3 Что копировать

![Выбор тегов и дополнительные настройки](img/connection-tags.png)

*Рис. 3. Выбор тегов и дополнительные настройки*

| Поле | Что значит |
|---|---|
| Какие теги копировать | Маски имён тегов из таблицы Runtime.dbo.Tag через запятую или с новой строки. `*` заменяет любые символы, `?` один символ. Пример: `Line1_*, Mixer_*`. Если оставить поле пустым, скопируются все теги историка |
| Кроме тегов | Маски тегов, которые не нужны. По умолчанию `Sys*`, это служебные теги самого историка |
| Забирать новые значения раз в, с | Как часто спрашивать историк о новых значениях. По умолчанию раз в 5 секунд |
| Загрузить историю за последние, ч | Сколько прошлого скопировать при первом запуске: 24 означает сутки, 168 неделю, 0 только новые значения |
| Копировать и строковые теги | Текстовые теги вроде имени рецепта или номера партии. Обычно флажок оставляют включённым |

> **Совет.** Для первой проверки возьмите несколько знакомых тегов (например `Line1_*`) и историю за 24 часа. Когда убедитесь, что данные сходятся с историком, расширьте маски: новые теги подхватятся сами.

Маску можно проверить заранее в SSMS. Подчёркивание в LIKE берётся в квадратные скобки:

```sql
SELECT TagName, Description, TagType
FROM Runtime.dbo.Tag
WHERE TagName LIKE 'Line1[_]%'
ORDER BY TagName;
```

### 7.4 Дополнительно

Этот раздел страницы свёрнут. Трогать его стоит, только если что-то не работает:

| Поле | Когда менять |
|---|---|
| Драйвер | По умолчанию выбирается сам: для логина SQL Server это Microsoft ODBC Driver 18, для учётной записи Windows FreeTDS. Если с одним драйвером подключиться не удаётся, попробуйте другой |
| Режим выборки | Delta отдаёт каждое изменение так, как его записал историк, этот режим и рекомендуется. Cyclic отдаёт одно значение на каждый шаг, и строк получается меньше, если теги меняются очень часто |
| Шаг для Cyclic, мс | Нужен только в режиме Cyclic |
| Часовой пояс ответа | Пустое поле значит, что историк сам отдаёт время в UTC. Если проверка пишет про wwTimeZone, укажите пояс сервера историка, например `Europe/Moscow` |
| Связанный сервер | Нужен, только если вы подключаетесь не к самому историку, а к другому SQL Server, где историк подключён связанным сервером (обычно `INSQL`) |
| Не брать последние, с | Самые свежие секунды историк может ещё дописывать. По умолчанию 3 |
| Перекрытие, с | При каждом обмене приложение немного перечитывает уже скопированное, чтобы подхватить опоздавшие значения. По умолчанию 30 |

### 7.5 Проверка и запуск копирования

Нажмите «Проверить подключение». Приложение пройдёт три шага:

1. Подключение: удалось ли войти, какие версии SQL Server и историка, что показывают часы сервера.
2. Список тегов: сколько тегов подходит под маски, и первые из них.
3. Чтение значений: значения за последние 10 минут и оценка, сколько строк в сутки придётся копировать.

![Проверка прошла: подключение, теги и значения в порядке](img/check-ok.png)

*Рис. 4. Проверка прошла: подключение, теги и значения в порядке*

Если какой-то шаг не прошёл, под ним написано, что случилось и что делать (подробнее в разделе 14). Исправьте настройки и проверьте ещё раз.

Когда все три шага зелёные, нажмите «Сохранить и начать копирование», и приложение перейдёт на страницу «Загрузка». Настройки хранятся в базе, поэтому после перезапуска компьютера или контейнеров копирование продолжится само.

Ту же проверку с сохранёнными настройками можно запустить из PowerShell:

```powershell
docker compose exec app python -m app.check
```

Страница «Загрузка» показывает, как идёт копирование. Она сама обновляется каждые 3 секунды, а коротко состояние видно в правом верхнем углу любой страницы.

*Рис. 5. Страница «Загрузка»: копирование идёт*

| Плитка | Что показывает |
|---|---|
| Копирование | «Идёт»: забираются новые значения. «Загрузка истории»: копируется прошлое, ниже виден процент. «Подключение…». «Ошибка»: причина написана в красной рамке, повтор будет сам. «Остановлено» |

### 9.1 Графики

![Страница «Графики»: теги с разными единицами на одном графике и пики из скрипта](img/charts.png)

*Рис. 7. Страница «Графики»: теги с разными единицами на одном графике и пики из скрипта*

1. Слева, на вкладке «Теги», найдите тег по имени или описанию и щёлкните по нему. Он ляжет на выделенный график, у которого слева синяя черта. Повторный щелчок убирает тег.
2. Чтобы наложить несколько тегов на один график, щёлкайте по ним по очереди. Для отдельного графика нажмите «Новый график» под графиками и выберите теги. Щелчок по названию графика делает его выделенным.
3. Кнопки «Все на один график» и «Каждый тег отдельно» раскладывают выбранное разом.
4. Период задаётся кнопками (от 15 минут до 30 дней) или полями «с» и «по» с кнопкой «Показать». Если включено «обновлять каждые 5 с», графики сами дорисовывают новые значения.

У каждой единицы измерения на графике своя шкала. Например, температура (°C) будет слева, а ток (A) справа, и подписи шкалы окрашены в цвет её тега. Теги с одинаковой единицей делят одну шкалу. Над графиком легенда: значение в точке под курсором (или последнее) с единицей. Щелчок по имени скрывает и снова показывает ряд, крестик убирает его с графика.

Числовые и дискретные теги рисуются ступенькой, потому что значение держится до следующего изменения, как его записал историк. На длинных периодах точки усредняются, но вокруг линии остаётся бледная полоса от минимума до максимума внутри каждого шага, и короткие выбросы не теряются. Строковые теги (рецепт, номер партии) показываются таблицей изменений под графиком.

### 9.3 Скрипты

Скрипт — это несколько строк на языке, похожем на Python. Он берёт значения тегов из базы приложения за выбранный период и показывает результат на графике и в выводе. Ни историк, ни база от скрипта не меняются: скопированные данные остаются полными, а отбор делается в момент показа.

> **Совет.** Если вы раньше не программировали, начните с руководства для начинающих. Оно открывается ссылкой на странице «Скрипты», а ещё лежит в `docs/SCRIPTS.md` и в Word-версии `docs/Скрипты.docx`. В нём есть первый скрипт за две минуты, готовые рецепты, справочник функций и разбор ошибок.

![Страница «Скрипты»: связь двух тегов и линейная модель](img/scripts.png)

*Рис. 9. Страница «Скрипты»: связь двух тегов и линейная модель*

```python
# Пики температуры выше 60 °C, не чаще одного за 10 минут
t = tag("Mixer1_Temp")
p = peaks(t, level=60, distance="10m")
show(t)
show(p, "пики")
print("пиков:", count(p))
```

1. Начните с примера из колонки «Примеры» слева, в него подставится один из ваших тегов. Или нажмите «Новый скрипт».
2. Имя тега удобно вставлять полем «Вставить тег»: начните вводить имя и выберите тег из списка.
3. Выберите период и нажмите «Выполнить» (или Ctrl+Enter). Если в скрипте ошибка, появится сообщение с номером строки, а сам номер слева станет красным.
4. Дайте скрипту название и нажмите «Сохранить». Сохранённый скрипт появится на странице «Графики» на вкладке «Скрипты», и его результат можно положить на любой график рядом с тегами. Пики рисуются кружками на линии своего тега.

| Задача | Как написать |
|---|---|
| Только пики | `peaks(t, level=80, distance="10m")`: максимумы не ниже 80, не чаще раза в 10 минут. Минимумы ищет `valleys(…)` |
| Значения выше порога | `above(t, 80)`, `below(t, 20)`, `between(t, 20, 80)`. Линию порога на графике рисует `const(80, t)` |
| Сколько времени выше порога | `duration(t > 80)` в часах, `duration(t > 80, "min")` в минутах |
| Моменты пересечения порога | `crossings(t, 80, "up")` |
| Значения при условии по другому тегу | `where(t, run == 1)`: температура, пока насос работает |
| Разность и другие расчёты | `a - b`, `a / b * 100`, `smooth(t, "5m")`, `rate(t, "1m")`, `shift(t, "30s")` |
| Числа за период | `mean(t)`, `min(t)`, `max(t)`, `std(t)`, `count(p)`, `quantile(t, 0.95)` |
| Связь тегов | `corr(a, b)` считает корреляцию, `fit(y, x1, x2)` строит линейную модель y ≈ a + b·x1 + c·x2 и выводит R², а результатом даёт расчётный ряд |

Полный список функций с пояснениями есть на самой странице, в разделе «Справка» под редактором. Интервалы пишутся так: `"30s"`, `"5m"`, `"2h"`, `"1d"` (можно и `"5мин"`, `"2ч"`). Строка без присваивания сама показывает результат: ряд на графике, число в выводе.

> **Примечание.** Скрипт выполняется внутри приложения, и возможностей у него немного: присваивания, арифметика, сравнения и функции из справки. Циклов, импорта, доступа к файлам и сети нет. За один запуск можно взять до 20 тегов и до 500 000 значений одного тега. Если значений больше, сократите период.

### 10.1 Сверка с историком

Чтобы убедиться, что копия совпадает с оригиналом, выполните в SSMS запрос по тому же тегу и сравните результат с панелью «Последние 500 строк за период»:

```sql
SELECT DateTime, TagName, Value, vValue, Quality
FROM Runtime.dbo.History
WHERE TagName = 'Line1_Route'
  AND DateTime >= DATEADD(hour, -1, GETDATE())
  AND wwRetrievalMode = 'Delta'
ORDER BY DateTime DESC;
```

SSMS показывает время в часовом поясе сервера историка, а Grafana и приложение по часам вашего компьютера. Обычно пояса совпадают. Самых свежих 3–8 секунд в базе может ещё не быть, они появятся при следующем обмене.

### 10.2 Свои панели

Чтобы менять дашборды, войдите в Grafana кнопкой «Sign in» справа вверху. Логин и пароль берутся из `GRAFANA_ADMIN_USER` и `GRAFANA_ADMIN_PASSWORD` в `.env`, по умолчанию admin и admin, и Grafana сразу предложит сменить пароль. Затем на дашборде выберите Edit, Add, Visualization, источник данных «Historian DB», режим запроса Code и напишите запрос, например:

```sql
SELECT $__timeGroupAlias(v.ts, $__interval), t.name AS metric, avg(v.value) AS value
FROM tag_value v
JOIN tag t ON t.tag_id = v.tag_id
WHERE t.name IN ('Line1_Temp', 'Line2_Temp')
  AND $__timeFilter(v.ts) AND v.quality = 0
GROUP BY 1, 2
ORDER BY 1
```

Для своих запросов пригодятся такие таблицы базы:

| Таблица | Что в ней |
|---|---|
| tag | Справочник тегов: tag_id, name (имя в историке), description, unit, datatype (float64 для аналоговых, bool для дискретных, string для строковых), active |
| tag_value | Значения: ts (время в UTC), tag_id, value (число), value_text (текст), quality (0 хорошее, 1 плохое в историке) |
| tag_latest | Последнее значение каждого тега (это представление) |
| tag_sync | До какого момента скопирован каждый тег и сколько у него строк |

> **Примечание.** Дашборд «Теги историка» поставляется файлом `grafana/dashboards/historian.json`. Изменения, сохранённые в Grafana, живут, пока этот файл не изменится, например при обновлении приложения. Поэтому свои дашборды лучше сохранять отдельно, через «Save as».

### 11.1 Доступ с других компьютеров

Приложение и Grafana открываются с любого компьютера сети по адресу этого ПК: `http://<IP этого компьютера>:8000` и `:3000`. IP-адрес покажет команда `ipconfig`, строка IPv4-адрес. Если с других компьютеров страницы не открываются, разрешите порты в брандмауэре Windows (PowerShell от имени администратора):

```powershell
New-NetFirewallRule -DisplayName "historian2grafana" -Direction Inbound -Protocol TCP -LocalPort 8000,3000 -Action Allow
```

> **Важно.** Страница «Подключение» доступна всем, кто может зайти на порт 8000, и там можно поменять настройки или остановить копирование. Открывайте порт 8000 только для своей сети.

### 11.2 Смена паролей

Пароль администратора Grafana меняется в самой Grafana: значок профиля, «Change password». Можно и командой:

```powershell
docker compose exec grafana grafana cli admin reset-admin-password НовыйПароль
```

GRAFANA_DB_PASSWORD достаточно поменять в `.env` и выполнить `docker compose up -d`, приложение само обновит пароль в базе.

DB_PASSWORD после первого запуска меняют в два приёма: сначала в базе, потом в `.env`, и затем выполняют `docker compose up -d`. Команда для базы:

```powershell
docker compose exec db psql -U historian -d historian -c "ALTER USER historian PASSWORD 'НовыйПароль';"
```

### 11.3 Обновление приложения

При обновлении сохраняются скопированные данные, настройки подключения, сохранённые скрипты и файл `.env`. Номер версии виден внизу каждой страницы приложения, а что изменилось, записано в файле CHANGES.md проекта.

#### Docker Desktop

Если проект получен через git, выполните `git pull` и затем `docker compose up -d --build`. Если архивом, замените файлы проекта новыми (файл `.env` сохраните) и выполните `docker compose up -d --build`.

#### Комплект без Docker (компьютер без интернета)

Новая версия переносится архивом-обновлением. В нём только файлы программы, без Python, PostgreSQL и Grafana, поэтому весит он меньше мегабайта. Собрать архив можно на любом компьютере с папкой проекта, интернет для этого не нужен:

```powershell
powershell -ExecutionPolicy Bypass -File offline\build-offline.ps1 -Update
```

Получится `dist\historian2grafana-update-<версия>.zip`. Внутри лежат папка `historian2grafana-offline` с файлами программы и «Как обновить.txt» с теми же шагами, что ниже. На компьютере с комплектом:

1. Остановите приложение: закройте окно `start.bat` и запустите `stop.bat`.
2. В папке комплекта, там, где лежит `start.bat`, удалите папки `app` и `web`. Папку `data` и файл `.env` не трогайте.
3. Откройте архив и скопируйте содержимое папки `historian2grafana-offline` в папку комплекта. Когда Windows спросит про совпадающие файлы, выберите «Заменить файлы в папке назначения».
4. Запустите `start.bat`. В первой строке окна должно быть «historian2grafana <версия> — запуск».
5. Если браузер уже был открыт, обновите страницу с очисткой кэша, Ctrl+F5.

База дообновится сама при первом запуске, а копирование продолжится с места остановки и догрузит из историка всё пропущенное.

> **Примечание.** Если в CHANGES.md сказано, что новой версии нужны новые библиотеки Python, архива-обновления не хватит. Тогда соберите полный комплект (README.md, раздел «Установка на компьютер без интернета») и замените в папке комплекта всё, кроме папки `data` и файла `.env`.

### 11.4 Резервные копии

Отдельные резервные копии не нужны. Источник данных — историк, и всё скопированное можно загрузить заново кнопкой «Загрузить заново». Настройки подключения занимают одну страницу, их проще ввести снова.

## 12. Сколько места занимают данные

Проверка подключения оценивает, сколько строк в сутки придётся копировать. Одна строка занимает в базе около 80–100 байт, а данные старше 7 дней сжимаются в 10–20 раз. Например, миллион строк в сутки дадут около 100 МБ в сутки в первую неделю и 5–10 МБ в сутки после сжатия.

Если места мало, сузьте маски тегов, уменьшите глубину первой загрузки или включите режим Cyclic с крупным шагом для быстро меняющихся аналоговых тегов. Текущий размер виден на странице «Загрузка», плитка «Размер базы».

Образы собирают на любом компьютере с интернетом и Docker Desktop и переносят файлом.

На компьютере с интернетом, в папке проекта:

```powershell
docker compose build
docker compose pull db grafana
docker save -o historian2grafana-images.tar historian2grafana-app:latest timescale/timescaledb:latest-pg16 grafana/grafana:11.6.0
```

Перенесите на целевой компьютер папку проекта и файл `historian2grafana-images.tar` (около 1,5 ГБ). На целевом компьютере, в папке проекта:

```powershell
docker load -i historian2grafana-images.tar
Copy-Item .env.example .env
docker compose up -d
```

Обратите внимание: здесь `docker compose up -d` запускается без `--build`. Образ приложения уже загружен, собирать его заново не нужно, а без интернета и не получится.

## 14. Неполадки

### 14.1 Docker и запуск

| Что видно | Причина и что делать |
|---|---|
| `docker` не найдена или error during connect | Docker Desktop не установлен или не запущен. Запустите его и дождитесь «Engine running» |
| Сборка падает на apt-get, curl или pip: Could not resolve host, timeout | Нет интернета или нужен прокси. Настройте прокси в Docker Desktop (раздел 3) или перенесите образы (раздел 13) |
| port is already allocated / Bind for 0.0.0.0:8000 failed | Порт занят другой программой. Поменяйте APP_PORT или GRAFANA_PORT в `.env` и выполните `docker compose up -d` |
| http://localhost:8000 не открывается | Проверьте командой `docker compose ps`, все ли контейнеры в состоянии Up, и посмотрите, что пишет приложение: `docker compose logs --tail 50 app`. Сразу после запуска подождите полминуты, пока готовится база |
| Контейнер h2g-app постоянно перезапускается | Смотрите `docker compose logs app`. Если приложение пишет про пароль базы, значит, DB_PASSWORD в `.env` поменяли после первого запуска (раздел 11.2) |

### 14.2 Подключение к историку

| Сообщение проверки | Причина и что делать |
|---|---|
| сервер не отвечает | Неверное имя или порт, сервер недоступен по сети или мешает брандмауэр. Пройдите раздел 6 и укажите полное имя с доменом или IP-адрес |
| Login failed for user … (18456) | Неверный логин или пароль, учётная запись заблокирована или у неё нет права читать базу Runtime. Учётная запись Windows пишется как ДОМЕН\логин |
| соединение оборвалось при входе (20002) | Чаще всего это неверный пароль, или сервер не принимает вход по NTLM. Попробуйте другой драйвер (раздел «Дополнительно», поле «Драйвер») или логин SQL Server |
| ошибка SSL / TLS / certificate | Старый SQL Server без современного шифрования. Поставьте `HISTORIAN_OLD_TLS=1` в `.env`, выполните `docker compose up -d` и проверьте снова. Можно также выбрать драйвер FreeTDS |
| wwTimeZone | Историк не принимает параметр часового пояса. Укажите пояс сервера в поле «Часовой пояс ответа», например Europe/Moscow |
| Invalid object name … History | Это не база историка, проверьте поле «База» (Runtime). Если вы подключаетесь к другому SQL Server, заполните «Связанный сервер» |
| не подошёл ни один тег | Маски ничего не выбрали. Проверьте маску запросом в SSMS (раздел 7.3). Помните, что `*` означает любые символы |
| Значений нет (шаг «Чтение значений») | Это не ошибка: выбранные теги за последние 10 минут не менялись. Копирование можно запускать |

### 14.3 Данные и графики

| Что видно | Причина и что делать |
|---|---|
| Долго идёт «Загрузка истории» | Много тегов или большая глубина истории. Копирование продолжится само, ход виден в процентах. Можно сузить маски или уменьшить глубину и нажать «Загрузить заново» |
| Отставание растёт | Обмен длится дольше периода опроса: слишком много тегов или историк отвечает медленно. Увеличьте «Забирать новые значения раз в» или сузьте маски |
| Время на графиках сдвинуто на несколько часов | Историк отдаёт время не в UTC. Укажите пояс сервера в поле «Часовой пояс ответа», затем нажмите «Загрузить заново» |
| Grafana: No data | Не выбраны теги, в выбранном периоде нет данных или копирование не запущено. Посмотрите страницу «Загрузка» |
| Grafana: password authentication failed for user grafana_reader | GRAFANA_DB_PASSWORD поменяли, а приложение не перезапустили. Выполните `docker compose up -d` |
| Тег есть в историке, но не в списке | Он не подходит под маски или попал под «Кроме тегов». Новые теги подхватываются в течение 10 минут |
| Скрипт: «… больше 500 000 значений — сократите период» | У тега очень частые значения. Выберите период короче |
| Скрипт: «тега … нет в базе приложения» | Имя написано с ошибкой или тег не копируется. Вставляйте имя полем «Вставить тег», а список копируемых тегов смотрите на странице «Загрузка» |

## 15. Частые вопросы

**Записывает ли приложение что-нибудь в историк?**  
Нет. Оно выполняет только запросы SELECT к базе Runtime и читает справочник тегов и историю значений.

**Насколько свежие данные на графиках?**  
Раз в 5 секунд приложение забирает всё, что историк записал, кроме последних 3 секунд. Обычно значение появляется в базе через 5–10 секунд после записи в историк.

**Что будет, если историк или сеть недоступны?**  
На странице «Загрузка» появится ошибка, а приложение будет повторять попытки: сначала через 5 секунд, потом всё реже, до раза в 5 минут. Когда связь вернётся, оно докопирует пропущенное.

**А если выключить компьютер?**  
После включения и запуска Docker Desktop контейнеры стартуют сами, и копирование продолжится с того места, где остановилось. Пропущенное догрузится из историка.

**Нужно ли копировать все теги?**  
По умолчанию копируются все теги, кроме служебных Sys*. Для проверки удобнее начать с нескольких масок и расширять их потом.

**Можно ли поменять глубину истории потом?**  
Можно, но уже скопированные теги в прошлое сами не догрузятся. После изменения нажмите «Загрузить заново» на странице «Загрузка».

**Где хранится пароль историка?**  
В базе приложения, то есть в томе Docker на этом компьютере. Учётная запись, под которой Grafana читает базу, к настройкам доступа не имеет. И всё же для подключения лучше брать учётную запись только для чтения.

**Совпадает ли копия с историком один в один?**  
В режиме Delta совпадает: каждое записанное историком значение хранится со своим временем и качеством. Как сверить, описано в разделе 10.1.

**Можно ли копировать из историка только пики или значения выше порога?**  
Нет, и так сделано намеренно. Приложение хранит полную копию того, что записал историк. Если отбирать на входе, отобранное потом не перепроверишь, а для другого отбора придётся снова читать историк. Пики, пороги и связи тегов отбирают скрипты (раздел 9.3) уже по скопированным данным, причём сколько угодно раз и разными способами.
